# T-108: Hover-превью демки для тех, кто не в комнате

**Phase:** 5 — полировка
**Model:** Sonnet (feature)
**Estimate:** 0.5 сессии

## Контекст

Hover-превью демки в списке ГС (ScreenHoverPreview) существовало, но
работало только внутри своей комнаты: живой кадр берётся временной
LiveKit-подпиской, а подписаться можно лишь будучи участником комнаты
(`canPreview = c.id === activeVoiceChannelId`). Discord же показывает
карточку «Сейчас стримит» со скриншотом любому на сервере.

Решение: **стример сам заливает кадр**. Пока идёт демка в серверном ГС,
клиент стримера раз в 15 сек снимает кадр своего локального трека
(инфраструктура снапшотов T-053), даунскейлит до 480px (JPEG q0.7,
~20-60 КБ) и POST'ит на сервер. Сервер держит его в Redis с TTL 45 сек —
стрим кончился → превью само истекло, чистить нечего.

## Реализация (код готов)

- **ginzu**: `VoicePreviewUploadRequest {dataBase64}` (кап 384 КБ),
  `VoicePreviewResponse {dataUrl|null}`.
- **speedy** (`voice.ts`):
  - `POST /voice/:channelId/screen-preview` — только member сервера И
    реальный участник комнаты (`roomUsersKey` sismember — чтобы нельзя было
    подсунуть «превью» чужому стриму); Redis `EX 45`;
  - `GET /voice/:channelId/screen-preview/:userId` — member сервера,
    отдаёт data-URL или null.
- **polly**:
  - `snapshot.ts`: `snapshotTrack(track, {maxWidth, quality})` — даунскейл
    (старые вызовы совместимы);
  - `voice/screenPreviewUploader.ts` — фоновый цикл: подписка на voice
    store (`screenSharing && context==='channel' && connected`), первый
    кадр через 2 с, дальше каждые 15 с; ошибки не критичны (warn + retry
    следующим тиком). Запускается один раз в `App.tsx`;
  - `ScreenHoverPreview`: новый проп `channelId` + react-query фолбэк
    (`enabled: !isSelf && !track`, refetch 15 с) — скриншот виден сразу и
    остаётся единственным источником вне комнаты; в своей комнате его
    заменяет живой трек;
  - `ChannelList`: гейт `canPreview` снят — hover работает на любом
    стримящем в любом ГС сервера.

DM-звонки пропущены осознанно: в списке личек стримы не показываются,
роут принимает только серверные voice-каналы.

Гейты: `pnpm typecheck` (все пакеты), speedy-тесты 46/46. Миграций нет.

**Фикс после первого прогона (2026-07-05):** карточка спавнилась далеко от
строки при UI-масштабе 125/150% — `computePosition` не учитывал CSS `zoom`
на `<html>` (getBoundingClientRect отдаёт визуальные px, а fixed-слой живёт
под zoom). Теперь все координаты делятся на `getUiZoom()`, как в ContextMenu.

## DoD

- [x] Стример периодически заливает кадр; TTL убирает превью после стрима
- [x] Hover вне комнаты → серверный скриншот; в комнате → живой трек
- [x] POST принимается только от участника комнаты
- [ ] Ручной прогон: A стримит в ГС, B на том же сервере НЕ в комнате →
      hover по строке A показывает скриншот (обновляется ~раз в 15 с);
      B заходит в комнату → hover показывает живое видео; A останавливает
      стрим → через ≤45 с превью пропадает
