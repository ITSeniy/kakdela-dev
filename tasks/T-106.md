# T-106: GIF-аватарки, оживающие в войсе

**Phase:** 5 — полировка
**Model:** Sonnet (feature; чисто клиентская)
**Estimate:** 0.5 сессии + ручной прогон

## Контекст

Аватарку можно ставить анимированным GIF. Везде (чат, member list, DM) она
показывается **статичным первым кадром**; в голосовом канале аватар «оживает»,
пока человек говорит (speaking от LiveKit active speakers) — и в тайле
участника, и в мини-строке под войс-каналом в ChannelList.

Бэкенд не менялся: `image/gif` уже в whitelist файлового пайплайна
(magic-bytes детектится), ключ объекта получает расширение `.gif`, а
`users.avatarUrl` — просто текстовый URL. GIF-аватар определяется на клиенте
по расширению в URL (`isGifUrl`).

## Реализация (код готов)

- **`components/Avatar.tsx`**:
  - проп `animate?: boolean` — влияет только на GIF-аватары;
  - `GifPoster` — статичный первый кадр: `drawImage` анимированной картинки
    по спеке берёт первый кадр, рисуем его в `<canvas>` (центрированный
    квадратный cover-кроп, ×2 буфер под hi-dpi). Canvas может быть tainted —
    неважно, readback не делаем. Ошибка загрузки → fallback на живой `<img>`.
- **`voice/ParticipantTile.tsx`**: `animate={speaking}` (покрывает VoiceScreen
  и DmCallScreen).
- **`channels/ChannelList.tsx`**: `animate={row.speaking}` в строке участника
  войса (speaking есть только для активного канала — как и ring).
- **`profile/AvatarCropper.tsx`**: проп `allowGif` — GIF принимается без
  обрезки (кроп через canvas убил бы анимацию): анимированное превью,
  слайдер/drag скрыты, `onConfirm` получает исходный File.
- **`ProfileEditForm.tsx` / `ProfileSetupScreen.tsx`**: `allowGif` у кроппера,
  имя/тип файла по `blob.type` (`.gif` / `.jpg`), превью формы с `animate`,
  обновлённые подсказки.

Гейты: `pnpm --filter @kakdela/polly typecheck` чистый.
